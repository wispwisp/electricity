# F02 CI for Linux and Windows Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every push builds and tests the app on Linux and Windows with a cached static Qt and uploads both single-file binaries; a local script produces the same Linux executable.

**Architecture:** One CMake script (`scripts/build_qt.cmake`) builds static Qt on both OSes from SHA-256-pinned archives. One workflow with two jobs restores or builds that Qt, builds the `release` preset, runs CTest, checks the binary's dependencies, and uploads artifacts. The Linux job builds its binary with the same `scripts/build_linux_executable.sh` the owner runs locally.

**Tech Stack:** GitHub Actions (`ubuntu-24.04`, `windows-2022`), CMake script mode, bash, PowerShell, Qt 6.12.0 static, MSVC 2022, GCC 13.

**Spec:** `docs/superpowers/specs/2026-11-19-f02-ci-design.md`

## Global Constraints

- Qt 6.12.0 exactly; `cmake/QtVersion.cmake` stays the reference pin.
- Qt archives: `https://download.qt.io/official_releases/qt/6.12/6.12.0/submodules/<module>-everywhere-src-6.12.0.tar.xz`, SHA-256:
  - qtbase `a951bd163c7b80fc6b8c88d7668fb56abf91c152373e13c10666763238131307`
  - qtsvg `e4ab39534ec97987b1b9b60ef7f4d3253d5912a69f8c713a01753174a4029331`
  - qttools `8dab8f3611496486a470ad5f115ceea584f36bc22a2b8b6f6ebdbafbb8160693`
  (downloaded 2026-11-19, MD5 matched Qt's `md5sums.txt`).
- Qt configure flags (ADR 0004): `-static -release -qt-zlib -qt-libpng -qt-libjpeg -qt-pcre -qt-harfbuzz -nomake examples -nomake tests`; Windows adds `-static-runtime`; Linux adds `-feature-xcb -no-feature-wayland -no-feature-glib -no-feature-icu -no-feature-zstd -no-feature-libudev -no-feature-cups -no-feature-gtk3`. These match the container's Qt (checked in `/opt/qt` feature headers), so a runner with extra `-dev` packages can't add runtime dependencies. qttools gets `-no-feature-clang`.
- Modules: qtbase, qtsvg, qttools only.
- Actions: `actions/checkout@v7`, `actions/cache/restore@v6`, `actions/cache/save@v6`, `actions/upload-artifact@v7`; no third-party actions.
- Artifact names: `electricity-linux-x86_64`, `electricity-windows-x86_64.exe`; retention 30 days.
- clang-format/clang-tidy 18 in CI (`/usr/lib/llvm-18/bin` first in `PATH`).
- Every new file has an SPDX `GPL-3.0-or-later` header.
- Never push; the owner pushes and pastes CI results back.

## Review Focus

- **A Qt build that fails part-way must not be cached.** The save step runs only on a cache miss, and the default `success()` condition keeps it from running after a failed build. Pinned by Task 4's step layout.
- **A dependency check that passes vacuously** (`readelf` finds no NEEDED entries, or `dumpbin` output can't be parsed) must fail. Tasks 2 and 4 make zero entries an error.
- **A runner with extra `-dev` packages could make the CI binary need more system libraries than the local one.** So the Linux check is an allowlist of ADR 0004's system libraries, read from direct `NEEDED` entries, rather than a denylist. Task 5 compares the CI-style build with the container build.
- **Re-running `build_qt.cmake` over an old work dir** gives stale or confusing state, and deleting a wrongly-passed dir would be destructive. The script refuses an existing `QT_WORK_DIR` instead (Task 1).
- **Bumping Qt in `QtVersion.cmake` but not in the CI script** (or the reverse). Task 1's pin test fails.

### Task 4: Workflow and Windows dependency check

**Files:**
- Create: `.github/workflows/ci.yml`, `scripts/check_windows_deps.ps1`

**Interfaces:**
- Consumes: `scripts/build_qt.cmake` (Task 1), `scripts/build_linux_executable.sh` (Task 2), `scripts/quality_gates.sh` with `CI=true` (Task 3).
- Produces: `scripts/check_windows_deps.ps1 -Exe <path>`. It exits 0 and prints the DLL list when every DLL from `dumpbin /nologo /dependents` is a system DLL. It exits 1 on any violation, and also when no DLLs were parsed.

- [ ] **Step 1: Write `scripts/check_windows_deps.ps1`.**
  - A DLL is rejected if it matches `^(vcruntime|msvcp|ucrtbase|concrt|api-ms-win-crt-|qt6)` (case-insensitive).
  - Otherwise it is accepted if it matches `^(api|ext)-ms-win-` (OS API sets) or exists in `$env:SystemRoot\System32`.
  - Everything else is rejected.
  - Print `not a system DLL: <name>` per violation.
- [ ] **Step 2: Write `.github/workflows/ci.yml`.**
  - Triggers: `on: [push, workflow_dispatch]`, `permissions: contents: read`.
  - **Job `linux`** (`runs-on: ubuntu-24.04`, env `CMAKE_PREFIX_PATH: /opt/qt`), in order:
    1. checkout.
    2. `sudo apt-get update && sudo apt-get install -y` with: `ninja-build libfontconfig-dev libfreetype-dev libx11-dev libx11-xcb-dev libxext-dev libxfixes-dev libxi-dev libxrender-dev libxcb1-dev libxcb-cursor-dev libxcb-glx0-dev libxcb-icccm4-dev libxcb-image0-dev libxcb-keysyms1-dev libxcb-randr0-dev libxcb-render-util0-dev libxcb-shape0-dev libxcb-shm0-dev libxcb-sync-dev libxcb-util-dev libxcb-xfixes0-dev libxcb-xkb-dev libxkbcommon-dev libxkbcommon-x11-dev libgl-dev libegl-dev clang-format-18 clang-tidy-18 cppcheck`.
    3. `sudo mkdir -p /opt/qt && sudo chown "$USER" /opt/qt`.
    4. Cache restore (`id: qt`, path `/opt/qt`, key `qt-static-${{ runner.os }}-${{ hashFiles('scripts/build_qt.cmake') }}`).
    5. `if: steps.qt.outputs.cache-hit != 'true'`: `cmake -DQT_PREFIX=/opt/qt -DQT_WORK_DIR=${{ runner.temp }}/qt-work -P scripts/build_qt.cmake`.
    6. Same `if`: cache save with the same path and key.
    7. `scripts/build_linux_executable.sh`.
    8. `ctest --test-dir build-release --output-on-failure`.
    9. Upload `dist/electricity-linux-x86_64`.
    10. `if: always()`: upload `build-release/screenshots` as `screenshots-linux`.
    11. `PATH=/usr/lib/llvm-18/bin:$PATH scripts/quality_gates.sh`.
  - **Job `windows`** (`runs-on: windows-2022`, env `CMAKE_PREFIX_PATH: C:\qt-static`), in order:
    1. checkout.
    2. MSVC environment (pwsh): locate VS with `vswhere -latest -products * -requires Microsoft.VisualStudio.Component.VC.Tools.x86.x64 -property installationPath`, run `cmd /c "<vs>\VC\Auxiliary\Build\vcvars64.bat && set"`, and append each `NAME=value` line to `$env:GITHUB_ENV`.
    3. Cache restore (path `C:\qt-static`, same key form).
    4. On a miss: `cmake -DQT_PREFIX=C:/qt-static -DQT_WORK_DIR=C:/qw -P scripts/build_qt.cmake`. Keep the work dir short because of Windows path limits.
    5. On a miss: cache save.
    6. `cmake --preset release`, then `cmake --build build-release`.
    7. `ctest --test-dir build-release --output-on-failure`.
    8. `scripts/check_windows_deps.ps1 -Exe build-release/electricity.exe`.
    9. Copy to `dist/electricity-windows-x86_64.exe` and upload it.
    10. `if: always()`: upload `build-release/screenshots` as `screenshots-windows`.
  - All uploads use `retention-days: 30`.
- [ ] **Step 3: Lint.** Download actionlint v1.7.12 (linux_amd64 release tarball, checksum from the release's checksums file) into its own scratchpad directory. Run it on `.github/workflows/ci.yml`. Expected: no output, exit 0.

### Task 6: ADR, roadmap, gates

**Files:**
- Create: `docs/adr/0020-ci-qt-build.md` (from `0000-template.md`)
- Modify: `docs/adr/README.md` (index row 0020), `docs/roadmap.md` (F02 bullet)

- [ ] **Step 1: Write ADR 0020 "CI pipeline and Qt build in CI".** Decision bullets:
  - CI Qt is qtbase+qtsvg+qttools only (qttools without clang), which refines 0004's "same submodules".
  - The Linux system features are switched off explicitly to match the container.
  - One CMake script builds Qt on both OSes from SHA-256-pinned archives. It is where CI pins the Qt version (0003 "the CI workflow"), guarded by `qt_version_pin_matches_ci`.
  - The cache key is OS plus a hash of the script, saved right after the Qt build.
  - The Linux dependency check is an allowlist of direct NEEDED entries; the Windows check accepts only System32 DLLs and API sets.
  - clang-tidy checks all files in CI.
  - The Linux job builds via `build_linux_executable.sh`.
  - `windows-2022` is the oldest Windows image. The fallback is `windows-2025` with `vcvars64.bat -vcvars_ver=14.44`.

  Rejected: qt-everywhere archive (larger download, harder to pin per module); inline YAML build steps (two untested copies); denylist dependency check (misses new runner libraries); third-party MSVC setup action.
