# F07 Loads Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The user drags lamps, sockets and appliances from a new Loads palette group onto the canvas around the enclosure, plugs appliances into sockets (two per socket), wires lamps, sockets and the cooktop with the F06 wire tool, edits load power and cable length, all undoable.

**Architecture:**
- `panelcore`: a new `loads.json` catalog file (load types with picture size, power, terminals or plug-in flag, socket plug places) and enclosure picture sizes. `Project` gains placed loads (`l<n>`), plugging by reference (an appliance stores its socket and place), load outlines and placement rules, load terminals, the cable rule and wire length defaults, and loads that follow the enclosure's bottom edge.
- App: undo commands for loads and cable length. `LoadItem` draws a load with its caption, a socket's empty places and cords. `EditorScene` syncs load items, routes wires into load terminals, takes load drops from the palette and moves loads. `PaletteWidget` adds the Loads group. `PropertiesPanel` shows loads and the length of wires to loads.
- Same rules as F05/F06: commands call model methods and never touch items, callers check validity before pushing, the model emits one `changed()` per mutation.

**Tech Stack:** C++20, Qt 6.12.0 static (Core, Widgets, Svg; `QUndoStack` from Gui), Qt Test (core and offscreen GUI), Xvfb + xdotool for the smoke run.

**Spec:** `docs/superpowers/specs/2026-11-22-f07-loads-design.md`

  Socket plug places (where a plugged appliance's top centre hangs): place 1 `(4.5, 40.5)`, place 2 `(49.5, 40.5)`.
- Enclosure picture sizes (`enclosures.json` `width`, `height`): 12 → 280×244, 24 → 280×368, 36 → 280×492.
- Load geometry (core, `project.h`):
  - `LoadCaptionHeight = 9`: the band under a wired load's picture holding its caption.
  - A plug place's rect is the largest plug-in appliance size (36×36) with its top centre on the place point.
  - Outline: picture rect ∪ caption band (wired loads) ∪ both plug place rects (socket), as one bounding rect. A socket at (0, 0) has outline `QRectF(-13.5, 0, 81, 76.5)`. A plugged appliance's outline is its picture rect, which lies inside its socket's outline.
  - A plugged appliance's picture top-left = socket position + place point − (appliance width / 2, 0): place 1 → socket + (−13.5, 40.5), place 2 → socket + (31.5, 40.5).
  - Overlap checks skip plugged appliances (their socket's outline covers them) and a socket's own appliances.
- Load placement (scene): a dropped or moved load's picture is centred on the cursor (a move keeps the grab offset), and its top-left snaps to a 4.5 grid: `top-left = round(p / 4.5) * 4.5` per axis. The supply block, its "Supply" text and its letters form the supply area, which the scene checks (its width depends on the language). The model checks the enclosure and other loads.
- Power: whole watts, 1 to `MaxLoadPower = 15000`. A socket has power 0.
- Wire lengths: a new wire with a load end starts at `LoadWireLength = 15` m, unless it joins a cable, in which case it takes the cable's length. Other new wires keep `0.3` m. A cable length is `> 0` and `<= MaxWireLength = 500` m. The properties field is 0.5–500 m, step 0.5, 1 decimal place.
- Cable: wires whose ends lie on the same two sides. A side is a load id, or `panel` for any device, bar or supply terminal. At least one side must be a load.
- Enclosure size change: loads whose outline top is at or below the current enclosure's bottom edge (`top >= enclosure().size.height()`) move by the height difference, in the same mutation. The change is refused if a moved load's outline would overlap a load that stays.
- Ids: loads `l<n>` from a counter that only grows, never reused. Undo restores a deleted load under its old id and index. Terminal ids: `l<n>:L`, `l<n>:N`, `l<n>:PE`. Load terminal capacity is 2.
- Names: wired loads are numbered per type in `loads()` order (`loadNumber`). The caption is the translated catalog `caption` + `" "` + number: "Lamp 1", "Socket 2". Plug-in appliances have no caption, and their name is the translated catalog `name`.
- Load terminals are entered from above (`Exit::Up`).
- Z values: `LoadItem::PlacedZ` 1, `LoadItem::LiftedZ` 2. Existing values are unchanged.
- Scene item ids (`data(0)`): a load item carries its load id; the drag preview carries `loadPreview`.
- Object names: `loadBox`, `loadNameLabel`, `loadTypeLabel`, `powerSpin`, `plugStatusLabel`, `socketContentsLabel` and `lengthSpin`, `cableNoteLabel` (properties). Existing names stay. The right-click menu `deviceContextMenu` also opens for loads.
- Palette: a `Loads` group after `Protection`. Item text is `name + "\n" + tr("%1 W")` with the locale-formatted power; the socket's text is its name only. Tooltip: `<b>name</b><br>description`. Item data `PaletteWidget::LoadTypeRole = Qt::UserRole + 2`; drag MIME type `application/x-electricity-load`, carrying the load type id as UTF-8.

## Review Focus

- **A typed power or length lands on the object it was typed for**, even when the user finishes typing by clicking another load or wire on the canvas. Neither object gets the other's value. Task 10 `editFinishedByClickingAnotherObject`.
- **Switching the language with loads on the canvas:** captions and wire ends change language, and loads keep their places. Task 7 `captionsFollowLanguage`, Task 10 `loadPropertiesTranslated`.
- **Undo removes the load a wire in progress started from:** the wire in progress is cancelled with no crash, and the next click starts a new wire. Task 11 `undoCancelsWireFromRemovedLoad`.
- **Loads far from the panel:** Fit to window shows them all, and re-routing on a change stays quick. Task 7 `fitAndRoutingWithFarLoads`.
- **Dropping a plugged appliance back onto its own socket** (on either place): no undo step, and it stays in its place. Task 9 `dropOnOwnSocketIsNoEdit`.

    QString id, name, description;

```cpp
inline constexpr int MaxLoadPower = 15000;     // W
inline constexpr double LoadCaptionHeight = 9; // the band under a wired load's picture

struct PlacedLoad
{
    QString id;       // stable "l<n>"; empty until added
    QString type;     // catalog load type id
    QPointF position; // top-left of the picture, scene units; unused while plugged in
    int power = 0;    // W; 0 for a socket
    QString socket;   // the socket a plug-in appliance is plugged into, "" if none
    int place = 0;    // 1 or 2 while plugged in, else 0
    friend bool operator==(const PlacedLoad &, const PlacedLoad &) = default;
};

enum class LoadPlacement : std::uint8_t {
    Fits,
    OnEnclosure, // the outline overlaps the enclosure
    Overlaps,    // the outline overlaps another load's outline
    PlaceTaken,  // the plug place already holds an appliance
    Invalid      // unknown type, type changed, power out of range, a plug into something that
                 // isn't a socket or by a load that doesn't plug in, place not 1 or 2
};

[[nodiscard]] PlacedLoad loadFromType(const LoadType &type, QPointF position); // default power

// in Project:
[[nodiscard]] const QList<PlacedLoad> &loads() const;      // insertion order
[[nodiscard]] const PlacedLoad *load(QStringView id) const; // nullptr if absent
// 1-based among the loads of its type in loads() order; 0 if absent
[[nodiscard]] int loadNumber(QStringView id) const;
// the picture's top-left: its position, or hanging from its socket's place
[[nodiscard]] QPointF loadPosition(const PlacedLoad &load) const;
[[nodiscard]] QRectF loadOutline(const PlacedLoad &load) const;
// scene rect of a socket's plug place (1 or 2)
[[nodiscard]] QRectF plugPlaceRect(const PlacedLoad &socket, int place) const;
// ids of the appliances plugged into the socket, by place
[[nodiscard]] QStringList pluggedInto(QStringView socketId) const;
// a load with the same id is ignored, so a move can be checked
[[nodiscard]] LoadPlacement loadPlacement(const PlacedLoad &load) const;
// same id and index rules as addDevice; returns the id, "" if refused
QString addLoad(PlacedLoad load, qsizetype index = -1);
// removes its wires; a socket's appliances stay where they hung, unplugged
bool removeLoad(QStringView id);
bool updateLoad(const PlacedLoad &load);
```
